# Gestión Hospitalaria
Aplicar la metodología Scrum para planificar, desarrollar y entregar un sistema de gestión hospitalaria que permita administrar pacientes, citas médicas, historial clínico y personal médico.
Roles Asignados
• Product Owner: Representa al hospital y define los requerimientos del sistema.
• Scrum Master: Facilita el proceso Scrum, elimina impedimentos y asegura que el
equipo siga la metodología.
• Development Team: Grupo multidisciplinario encargado de diseñar, programar y
probar el sistema.
Requisitos del Sistema (Product Backlog inicial)
1. Registro de pacientes
2. Agenda de citas médicas
3. Consulta de historial clínico
4. Gestión de médicos y especialidades
5. Generación de reportes médicos
6. Autenticación y roles de usuario
Actividades del Ejercicio
1. Sprint Planning (Planificación del Sprint)
• Duración del Sprint: 2 semanas
• Seleccionar los ítems del Product Backlog que se desarrollarán en el Sprint 1
• Definir el Sprint Goal (Ejemplo: “Implementar el módulo de registro de pacientes y
agenda de citas”)
2. Daily Scrum (Reunión diaria)
• Simular reuniones de 15 minutos donde cada miembro responde:
o ¿Qué hice ayer?
o ¿Qué haré hoy?
o ¿Hay algún impedimento?
3. Sprint Execution (Ejecución del Sprint)
• Desarrollo colaborativo de los módulos seleccionados
• Uso de herramientas como Jira, Trello o tableros físicos para visualizar el progreso

4. Sprint Review (Revisión del Sprint)
• Demostración del sistema funcional al Product Owner
• Recopilación de retroalimentación para mejorar el producto
5. Sprint Retrospective (Retrospectiva del Sprint)
• Reflexión sobre lo que funcionó, lo que no y cómo mejorar en el próximo Sprint
Entregables
• Módulo funcional del sistema hospitalario
• Tablero Scrum actualizado
• Documentación técnica y de usuario
• Informe de retrospectiva
